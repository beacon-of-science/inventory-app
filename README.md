# 简库存

简库存是一款离线 Android 库存管理 App，适合日常物品及药品包装管理。商品、库存、单盒记录和 OCR 原文保存在手机本地，无需账号或服务器。

## 下载与安装

[下载 v1.0.0 安装包](https://github.com/beacon-of-science/inventory-app/releases/tag/v1.0.0)。手机只需要 APK，无需安装 Node.js。

| 安装情况 | 选择的文件 |
| --- | --- |
| 首次安装，或已安装正式签名版 | inventory-app-release.apk |
| 已安装此前的 Debug 测试版，希望保留数据覆盖升级 | inventory-app-debug.apk |

支持 Android 7.0（API 24）及以上，目标 Android API 36。正式包关闭调试；兼容升级包保留原 Debug 证书。两者应用标识相同、签名不同，不能直接互相覆盖。升级前先导出 JSON 备份；从 Debug 转正式签名版时，需确认备份已保存，再卸载旧版、安装正式版并导入备份。卸载会删除本地数据和恢复点。

Release 附有 SHA256SUMS.txt，供核对文件完整性。签名私钥不在仓库中；后续正式包沿用同一签名。签名机制可参阅 [Android 官方说明](https://developer.android.com/studio/publish/app-signing)。

## 可以做什么

- 商品新增、编辑、查看、删除，支持搜索、分类、低库存提醒及导入导出。
- 入库、出库、当前库存与历史记录；校验必填字段、数量和库存不足。
- 摄像头商品条码扫描与连续扫描，支持单盒实例、追溯码绑定和重复码保护。
- 多面包装 OCR，提取名称、规格、厂家候选，辅助核对入库信息。
- 商品、库存、记录之间左右滑动，按钮反馈、页面转场和 Android 分层返回。
- 统一的绿色库存盒标识，支持圆形桌面图标及 Android 13 以上的主题图标。
- 本地持久化、自动恢复点、备份恢复、减少动画设置及隐私受限的诊断记录。

## 开始使用

普通商品：新增商品后入库 5 件，再出库 2 件，库存应为 3 件；尝试出库 4 件会被拒绝，不会写入成功记录。数量使用正整数，计量单位由商品定义。

药品单盒：入库时拍摄包装，确认 OCR 信息，并按流程绑定单盒码或追溯码。不同包装面可分次拍摄，但必须来自同一盒；第一盒拍摄信息不会自动证明后续盒子一致。出库选择或扫描对应单盒，核对后完成操作。存在库存或关联单盒记录的商品不能直接删除。

每次操作后可以查看历史记录；重新打开 App 后数据应保留。重要操作前导出备份，并确认文件真实存在。

## OCR 怎样确认

OCR 读取文字后，用规则生成字段候选，并不保证能识别所有字体。候选进入表单后，仍应核对包装再确认。

**厂家优先使用英文企业名称。** 支持 Corporation、Corp.、Company、Co.、Ltd.、Limited、Inc.、LLC 等企业结尾；没有合适英文候选时使用中文。例如同一包装识别出 `QILU PHARMACEUTICAL CO., LTD.` 和错字中文厂家时，优先采用该英文候选，不会猜改中文错字。

- 单个合适候选可填入空白字段；多个英文厂家需要人工选择。
- 下拉列表保留中文候选供手动选择；已有商品资料和人工修改不会被自动覆盖。
- 支持 Manufacturer、Manufactured by、Manufacturing company 标签及同次拍摄中的合理折行；不跨拍摄、字段标签或说明边界拼接企业名。
- 剂量、地址、经销商、进口商等文字会参与排除；复杂版式仍可能需要手动校正。

英文和中文名称不会自动翻译或视为同一企业。历史资料中存在明确中文厂家冲突时，仍会按原校验规则阻止通过，应核对后校正错误资料。原始识别文字及旧记录快照保留，不会因候选规则更新而被升级成已验证信息。

每次核对支持 1–6 张包装面文字，每面最多 4000 字。名称、规格、厂家采用分字段核对：冲突阻止通过，信息不足需补拍或按提示人工确认。OCR 只辅助包装信息一致性判断，不证明药品真伪。

## 备份、恢复和异常处理

手动备份为 JSON，导入上限 5 MiB，兼容数据版本 1、2、3。导入先预览，通过确认后整体替换当前数据；取消不改变库存。导入或恢复前会先保护当前有效数据，保护失败则停止替换。

自动恢复点默认启用，最多保留 5 个，也可手动创建或在设置中关闭。恢复点和主数据都在手机本地，不能代替存放到外部位置的备份。

主数据损坏时进入只读恢复状态，避免继续写入。恢复前保存损坏原文；已有另一份损坏原文时，必须先导出留存并明确确认替换。损坏原文导出格式为 `inventory-app-raw`，用于保留证据，不能作为普通库存备份导入。

Android 使用系统文件选择器保存备份，写入并关闭成功后才报告完成；取消不会更新备份时间。浏览器开发预览只能报告已发起下载，需要自行检查文件。保存时进程被系统终止，文件可能不完整，应重新导出。

诊断记录最多 80 条，仅保留事件代码与时间，不保存商品名称、条码、OCR 原文或完整错误内容，也不自动上传。

## 开发与构建

技术栈：Vue 3 + JavaScript + Vant + Vite + Capacitor。网页预览用于开发，摄像头、原生 OCR、扫码与系统文件操作需在 Android APK 中验证。

已验证工具环境：Node.js 22.20、npm 10.9、JDK 21.0.11、Android SDK / Build Tools 36、Gradle 8.14.3、Android Gradle Plugin 8.13。项目要求 Node.js ≥ 22.12，依赖具体版本由 package-lock.json 锁定。

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

Debug APK：配置 Android SDK 和 JDK 后执行：

```sh
npm run android:debug
```

产物位于 `android/app/build/outputs/apk/debug/app-debug.apk`。也可先运行 `npm run android:sync`，再执行 `npm run android:open`，用 Android Studio 构建。每次修改网页代码后必须重新同步，避免 APK 使用旧页面。仓库包含 Gradle Wrapper。

正式 APK：在 Android Studio 中选择 Generate Signed Bundle / APK，使用自己的签名文件；也可为 Gradle 设置以下环境变量后构建 assembleRelease：

```text
INVENTORY_RELEASE_STORE_FILE
INVENTORY_RELEASE_STORE_PASSWORD
INVENTORY_RELEASE_KEY_ALIAS
INVENTORY_RELEASE_KEY_PASSWORD
```

不要提交签名文件或密码。自行构建使用不同签名时无法直接覆盖官方安装包。正式产物位于 `android/app/build/outputs/apk/release/app-release.apk`。

## 验证与真机复测

v1.0.0 的自动化验收包括 283 项 JavaScript 测试、Debug / Release 各 32 项原生单元测试，以及 APK 版本、签名、对齐和网页资源一致性检查。

此前 M5 功能已由用户在努比亚红魔 8S Pro、Android 15、Redmagic OS 10.0.12 上复测通过；用户随后反馈厂家专项复测也没有问题。真机反馈与上述构建验收分别记录，不把自动化或网页预览当作手机 OCR 识别质量证明。

建议复测：

1. 英文厂家和错误中文同时出现时优先填英文；无英文时回退中文。
2. 两个英文厂家候选必须选择，人工修改后补拍不会覆盖。
3. 核对识别拼写、多面属于同盒、真实字段冲突仍被阻止。
4. 覆盖升级后旧商品和库存正常；摄像头取消、返回键、备份导入和取消流程正常。

